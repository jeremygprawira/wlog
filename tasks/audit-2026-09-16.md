# wlog gap audit (2026-09-16)

This page lists the problems this audit found in the specs, the plan, the code, CI, and the docs. It also lists the decisions the spec and the interview never made, and the work that makes wlog better than evlog.

## How the audit ran

- One reviewer read SPEC.md, CAPABILITIES.md, plan.md, todo.md, SPEC-core, SPEC-http-std, SPEC-audit, SPEC-v1.2-additions, event-shape, customization, best-practices, evlog-parity, README, and the core package.
- Six parallel reviewers covered redact, sample, enrich, memory, and wlogtest. They also covered the HTTP and logger adapters, pipeline and drains, audit, catalog, llm, and herr, and the CLI. One compared wlog with evlog.dev: all 106 pages through llms-full.txt, plus releases up to evlog@2.29.0.
- The lead reviewer re-ran or re-read the top findings of every report before listing them.
- Status meanings: CONFIRMED means a repro program or a command showed it. READ means the code shows it, but no program ran. SUSPECTED means vendor docs point to it, and it needs a real run.
- The existing make targets pass: `make race`, `make compat` (Go 1.23.0), local `make lint` (golangci-lint 2.11.3), and `make map` (score 100). The tests miss every problem below.
- No repository file changed. A build during the audit edited `middleware/echo/go.mod`. It was reverted with `git checkout`.

Severity scale:

| Severity | Meaning |
|---|---|
| critical | Breaks a safety gate (G1 to G6), crashes or hangs the app, or loses audit data |
| high | Wrong data, a broken spec promise, or a failure a user hits in normal use |
| medium | A real defect with a workaround or a narrow trigger |
| low | Polish, docs, or a rare edge |

## Verdict

wlog is not ready for the v1.0.0 tag. The audit lists 21 critical, 47 high, 69 medium, and 30 low items. Many items hold more than one defect. Gates G1, G3, G4, and G5 each fail in more than one way. CI is red on every push. No sub-module builds outside the workspace.

Fix order:

1. REL-1 and REL-2, so CI and module builds tell the truth.
2. The G1 leaks: CORE-1, CORE-2, CORE-3, RED-2, RED-3, HTTP-1, HTTP-14, AUD-7.
3. The crashes and hangs: CORE-7, CORE-8, PIPE-1, PIPE-2, PIPE-3, HTTP-2, HTTP-8, RED-1.
4. Audit integrity: CORE-9, AUD-1 to AUD-6.
5. Then high items by area, then the SPEC gaps before new features.

## CORE: the root package

#### CORE-1 · critical · CONFIRMED · G1 · `plain.go:41`
`wlog.Info`, `Warn`, and `Debug` copy kv values into the event without `normalize`. The redactor walks only `map[string]any`, `[]any`, and `string` (`redact/redact.go:302-327`). A struct or a `map[string]string` passes unmasked.
Evidence: `wlog.Info(ctx, "user created", "user", user{Password: "hunter2"})` emitted `"password":"hunter2"`.
Fix: normalize kv values. Make the redactor mask any type it cannot walk.

#### CORE-2 · critical · CONFIRMED · G1 · `event.go:257-260`
`normalize` keeps a `map[string]any` or `[]any` as is and never looks inside. A `map[string]string`, `[]map[string]any`, `[]string`, or struct nested in a map is never walked. The same gap covers values that an Enricher or a Transform adds, and `WithRawValues`.
Evidence: `Set(ctx, "payload", map[string]any{"a": map[string]string{"password": "LEAK1"}})` emitted `LEAK1`.
Fix: normalize recursively, and make `Apply` fail closed on unknown types.

#### CORE-3 · high · CONFIRMED · G1 · `event.go:262-268`
When `json.Marshal` fails (a func, chan, or cycle field), `normalize` falls back to `fmt.Sprintf("%v")`. That prints fields tagged `json:"-"`.
Evidence: a struct with a `json:"-"` secret and a func field emitted `"{n sk_live_abcdef123456 0x...}"`.
Fix: on a marshal failure, store a marker such as `"[UNSERIALIZABLE:main.hidden]"`.

#### CORE-4 · high · CONFIRMED · `event.go:276-277`, `redact/redact.go:242`
Redaction edits the caller's own maps. `emit` makes a shallow copy, and `normalize` keeps the caller's map. After `end()`, the app's map holds `[REDACTED]`. A goroutine that still reads the map races with the redactor.
Evidence: `m := map[string]any{"password": "hunter2"}`, `Set`, `end()`, then `m["password"]` is `"[REDACTED]"`.
Fix: deep-copy tree values at `Set`, or before `Apply`.

#### CORE-5 · high · CONFIRMED · `event.go:364`
A `NaN` or infinite float anywhere makes `json.Marshal` fail for the whole event. Stdout loses the event. A JSON drain loses it. The audit journal drops the audit line with no error.
Fix: replace non-finite floats with a string in `normalize`.

#### CORE-6 · high · CONFIRMED · `event.go:262-270`
The JSON round trip turns every number inside a struct, and every `uint64`, into `float64`. An ID above 2^53 changes.
Evidence: `order{ID: 1<<60 + 1}` emitted `1152921504606847000`.
Fix: decode with `json.Decoder.UseNumber`, or convert with reflection.

#### CORE-7 · critical · CONFIRMED · G3 · `errors.go:94`
`wlog.Error` calls the `ErrorExtractor` with no recover, while it holds the event lock. A panicking extractor panics the handler. A typed nil error (`var e *MyErr; wlog.Error(ctx, e)`) panics inside `err.Error()`. A nil `*catalog.Registry` in `catalog.Extractor` panics too.
Fix: recover around `Extract`, store a fallback `ErrorInfo`, and report to OnError.

#### CORE-8 · high · CONFIRMED · G3 · `drain.go:57-61`, `stages.go:62`
The `OnError` callback runs inside the deferred recover of other hooks, with no recover of its own. A panicking `OnError` escapes to the caller.
Fix: wrap every `onError` call in recover.

#### CORE-9 · critical · CONFIRMED · G5 · `event.go:289`
The minimum-level filter runs before the audit bypass. `WithLevel(LevelWarn)` or `WLOG_LEVEL=warn` drops every successful audit record. `SetEnabled(false)` drops them too.
Fix: let events that carry `audit` skip the level filter. Decide and document the disabled case.

#### CORE-10 · high · CONFIRMED · `detach.go:37`
`Detach` returns a context that keeps the parent's cancellation. When the HTTP handler returns, the detached goroutine's context is canceled, so its database and network calls fail. `examples/detach` calls `sendEmail` in the same goroutine, which hides this.
Fix: use `context.WithoutCancel` inside `Detach`, and show a real `go func` in the example.

#### CORE-11 · high · CONFIRMED · G2 · `drain.go:42-46`, `event.go:354`
Core gives the same event map to every drain. Some drains edit that map: `audit.Chain`, `audit.Sign`, `audit.Journal`, and any user `DrainFunc`. Each one races with a `pipeline.Wrap` drain that reads the map on its own goroutine.
Evidence: `WithDrains(pipeline.Wrap(sender), audit.Chain())` gave `WARNING: DATA RACE` at `pipeline.go:139` and `audit/chain.go:47`.
Fix: document drains as read-only, move audit chaining into core before drains, and copy for any drain that must edit.

#### CORE-12 · high · CONFIRMED · `event.go:350-354`, `fields.go:53-89`
Field presets rename keys before drains run. Every drain reads `event["service"].(map[string]any)`, `timestamp`, and `level`. With `FieldsFlat()` or `FieldsOTel()`, Loki labels are empty and the OTLP resource is `{}`.
Fix: send the canonical event to drains and rename only for stdout, or pass the mapping to drains.

#### CORE-13 · medium · CONFIRMED · `fields.go`
`FieldsOTel()` and `FieldsFlat()` rename only `service.*` and five top-level keys. `http.*`, `trace.*`, and `error.*` never change, so the OTel preset does not give OTel names. `FieldsNamespaced()` and `FieldNames.Rename` from SPEC-core do not exist. The golden files for SPEC-core criterion 8 and plan C9 do not exist.
Fix: finish the presets with golden tests, or cut them from the spec.

#### CORE-14 · medium · CONFIRMED · `middleware/nethttp/middleware.go:29`
Every HTTP event has `operation: "http.request"`. SPEC-core and event-shape.md say the route. The pretty header shows `INFO http.request` for every request.
Fix: add a core call that sets the operation, and set it to the matched route, such as `POST /orders/{id}`.

#### CORE-15 · high · CONFIRMED · `event.go:289-296`, HTTP adapters
The HTTP status never sets the level. A 5xx without `wlog.Error` is `level: info`, `outcome: success`. A 404 is info. SPEC.md and SPEC-core say a 4xx is warn. Level-based sampling then drops 5xx events. evlog maps 400 and above to warn.
Fix: set warn for 4xx and error for 5xx unless `SetLevel` ran. Derive outcome from status and error.

#### CORE-16 · medium · CONFIRMED · `event.go:298`
`timestamp` is the emit time. SPEC-core says Start. event-shape.md says emit.
Fix: pick one and write it in both docs.

#### CORE-17 · medium · CONFIRMED · `detach.go:47-59`
A write after `end()` on a top-level event is dropped with no counter and no OnError call. SPEC-core criterion 4 says it counts. `TestCore_LateWrite_NoOpenAncestor_IsSilentNoop` locks in the silent drop. evlog prints a warning with the dropped keys.
Fix: report a late write with the operation and the key through OnError.

#### CORE-18 · medium · CONFIRMED · `event.go:69-72`, `plain.go:22-25`
If the context has no logger or no event, `Start`, `Set`, `Error`, `Info`, and `audit.Do` do nothing and give no signal. A job that calls `wlog.Error` without `Start` logs nothing. `wlog.Info(context.Background(), "server started")` prints nothing.
Fix: add a debug signal and decide on a default logger (SPEC-G14).

#### CORE-19 · medium · CONFIRMED · `wlog.go:21`, `drain/memory/named.go`
`SetEnabled` is process-wide package state, which CLAUDE.md forbids. It turns off every Logger, so parallel tests interfere. `memory.Named` adds a second package registry, which SPEC-v1.2 marks ask-first.
Fix: make them per Logger, or record the exception in CLAUDE.md.

#### CORE-20 · medium · CONFIRMED · `event.go:356-369`
SPEC-core defines `WithSinks` and a `Sink` interface. Neither exists. Output always goes to `os.Stdout`, with one unbuffered write per event on the request goroutine. A stalled stdout pipe blocks every request.
Fix: add a writer option, and consider a buffered async stdout.

#### CORE-21 · medium · CONFIRMED · `drain.go:42-46`
Drains run one after another on the request goroutine. SPEC-core says concurrently. A `DrainFunc` that sleeps 300ms makes the response take 302ms. Only `pipeline.Wrap` protects the request.
Fix: document that network drains need `pipeline.Wrap`, or dispatch async by default.

#### CORE-22 · medium · CONFIRMED · `pretty.go`
The pretty sink writes each field with its own write, so lines from concurrent requests interleave. Nested maps print in Go syntax (`map[method:GET ...]`). The header has no method, path, or status. If stdout is not a terminal, colors still print. SPEC-core says `NO_COLOR` picks the format, but the code uses it only for color. Only env `local` and `dev` turn pretty on.
Fix: build each event in a buffer and write once, render a tree, and detect a TTY.

#### CORE-23 · medium · CONFIRMED · `event.go:102`
`Set` replaces a map value. `SetGroup` merges one level only. evlog deep-merges.
Fix: decide the merge rule and document it.

#### CORE-24 · medium · CONFIRMED · `errors.go:48,58`
The default extractor uses a type assertion for `Code()` and `Stack()`, not `errors.As`. A `%w`-wrapped catalog error loses its code. `errors.Join` shows no separate causes. There is no error type name and no caller file:line.
Fix: use `errors.As`, list joined causes, and add `type`.

#### CORE-25 · medium · READ · G4 · `event.go:37-43`
Caps count top-level keys, group fields, and array length. Nothing caps a nested map passed to `Set` or the total event size. 200 keys of 60KB strings are allowed. Datadog rejects a log over 1MB.
Fix: add a total-bytes cap with a truncation marker.

#### CORE-26 · low · CONFIRMED · `event.go:262`
`Set(ctx, "err", err)` stores `{}`. `Set(ctx, "wait", 1500*time.Millisecond)` stores `1500000000`.
Fix: store `err.Error()`, and a duration in milliseconds or as text.

#### CORE-27 · low · CONFIRMED · `event.go:301`
`duration_ms` is whole milliseconds, so fast requests show 0. `http.duration_ms` repeats it with a different start time.
Fix: use a float or microseconds, and keep one duration.

#### CORE-28 · low · READ · `detach.go:19`, `key.go`
`Detach` does not apply StrictKeys. StrictKeys looks only at `Set`, not at `SetGroup` or `Append`. Env `development` does not count as development.

#### CORE-29 · low · READ · `wlog.go:84`
`WithService("orders", "", "")` erases `WLOG_VERSION` and `WLOG_ENV`. With zero config there is no `service` key, although SPEC-core criterion 1 says every reserved key is present.

#### CORE-30 · low · READ · `level.go`
`SetLevel(ctx, "bogus")` and `WithLevel("x")` are accepted. An unknown level ranks 0, so nothing is filtered.

#### CORE-31 · low · READ · `plugin.go:61`
Only the first Keeper plugin is used. If `WithSampler` is set, no Keeper plugin is used. Nothing reports this. SPEC-core criterion 5 implies several keepers. `Plugins()` returns the internal slice. `RequestFinisher` cannot see the event.

#### CORE-32 · low · READ · `drain.go:66`
`Close` does not stop later emits. It closes drains one by one, so one slow drain uses the whole deadline.

#### CORE-33 · low · READ · `redactor.go:23-28`
`WithRedactor(nil)` stores nil, so `currentRedactor` builds `redact.Default()`, with regex compiles, for every event.

#### CORE-34 · low · CONFIRMED · event shape
Counters and the fingerprint are flat dotted keys (`wlog.dropped_fields`, `redact.fingerprint`), while `service` and `http` are nested objects. Empty maps and an empty `user_agent` are emitted. Header names keep canonical case (`Content-Type`), while every other key is snake_case. Changing reserved keys is ask-first.

## RED: redaction

#### RED-1 · critical · CONFIRMED · G3 · `redact/redact.go:333-343`
`matchesKey` tries every run of tokens in a key and builds a string for each run. Its cost grows with the cube of the key length. A client controls header, query, cookie, and body key names.
Evidence: one 2000-byte key took 1.13s to redact. A 4000-byte query key took 8.4s through the middleware.
Fix: limit runs to the longest denylist entry, and compare token slices without building strings.

#### RED-2 · critical · CONFIRMED · G1 · `redact/redact.go:164-169`
`Redactor.With` copies only keys, client IP masking, the replacement text, and the limits. It drops custom patterns, the pattern toggles, transforms, and `ReplaceFunc`. The runtime swap in the spec, `SetRedactor(r.With(...))`, weakens redaction with no error. `Disabled().With(...)` masks every value with empty text.
Fix: keep the full resolved config on the Redactor, and start `With` from it.

#### RED-3 · critical · CONFIRMED · G1 · `redact/defaults.go`, `redact/tokenize.go`
A key written as one word never matches a two-token entry. The spec says `apikey` and `api_key` are the same entry, but they are not.
Not masked by default:

- API keys and tokens: `apikey`, `accesstoken`, `refreshtoken`, `authtoken`, `clientsecret`
- sessions: `sessionid`, `JSESSIONID`, `PHPSESSID`, `connect.sid`, `sid`, `csrftoken`
- passwords and keys: `newpassword`, `passphrase`, `access_key`, `signing_key`
- connection data: `dsn`, `database_url`, `X-Amz-Signature`

Cookies are captured by default, so session cookies leak with zero config.
Fix: also match joined tokens, mask cookie values by default, and extend the list. The list change is ask-first.

#### RED-4 · high · CONFIRMED · G4 · `redact/redact.go:27-41`
The token cache is a `sync.Map` with no size limit, keyed by client-chosen key names. 200,000 unique keys kept 58MB after GC.
Fix: cap the cache, or cache only short keys.

#### RED-5 · high · CONFIRMED · `redact/custom.go:62`
`EnablePatterns("nikk")`, a typo, returns no error, and NIK values leak. SPEC-redact criterion 3 requires an error.
Fix: test each name against the built-in list.

#### RED-6 · medium · CONFIRMED · G1 · `redact/patterns.go`
Value patterns miss common secrets:
- DSN credentials, such as `postgres://app:hunter2@db:5432/x`
- URL query secrets, such as `?token=`, `?access_token=`, and `code=`
- `Basic` auth, `sk_live_` keys, and AWS `AKIA` keys

A reset token in a `Referer` header passed unmasked in the README quick start. Map keys are never scanned.
Fix: add URL-credential and URL-query patterns.

#### RED-7 · medium · CONFIRMED · `redact/patterns.go`, `redact/patterns_id.go`
Built-in patterns damage normal data:
- The ipv4 pattern turns every Chrome user agent into `Chrome/***.***.***.0`.
- The card pattern masks about 10% of 13-digit millisecond timestamps and 19-digit snowflake IDs. `1726473600004` became `****0004`.
- Phone and IBAN patterns over-match. `maskPhone` adds a `+62` prefix to a number with no country code.

Fix: tighten the patterns. Pattern changes are ask-first.

#### RED-8 · medium · CONFIRMED · `redact/redact.go:395-398`
`Fingerprint` hashes only the key list. Patterns, transforms, the replacement, and the disabled flag do not change it. `Disabled()` and `ReplaceKeys()` share one fingerprint.
Fix: hash the whole effective config.

#### RED-9 · medium · CONFIRMED · `redact/redact.go:252-261`
A panicking transform fails open, and the event keeps the data the transform was meant to remove. SPEC-redact says fail closed. Plan R7 says the opposite of the spec.
Fix: fail closed, and align the plan.

#### RED-10 · medium · CONFIRMED · SPEC-redact, SPEC-core, `redact/match.go`, tests
Every path example uses `http.request.headers.*` and `http.request.body`. The real shape is `http.request_headers` and `http.request_body`. A user who copies the docs gets no masking and no error. The test uses the invented shape, so it passes.
Fix: correct the docs and fixtures. Warn about a path rule that can never match a reserved shape.

#### RED-11 · medium · CONFIRMED · `redact/fuzz_test.go`, `gates_test.go`, `Makefile:12`, `.gitignore`
The fuzz tests vary only a value under one fixed key. They never vary key names, nesting, types, plain lines, or enrichers, so they missed CORE-1 and CORE-2. `make fuzz` and CI run one of the three fuzz targets. `testdata/fuzz/` is in `.gitignore`, so crash inputs are not kept as regression tests.
Fix: fuzz whole event shapes, run every target, and commit crash inputs.

#### RED-12 · low · CONFIRMED · `redact/match.go`, `redact/redact.go`, `redact/custom.go`
- Globs use `path.Match`, so `*` does not cross `/`.
- `RemoveKeys` removes one exact copy and ignores token form. `RemoveKeys("apiKey")` fails.
- Negative limits, and a regex that matches the empty string, are accepted.
- The `NoBuiltinPatterns` doc disagrees with the code.
- The comment at `patterns.go:19` says Go regexp backtracks. It runs in linear time.
- `BENCH.md` records 23 allocs per op against a target of 10, and the spec was not updated as R8 requires.

## HTTP: middleware, framework adapters, logger adapters, trace

#### HTTP-1 · critical · CONFIRMED · G1 · `middleware/nethttp/body.go:45-54`
A body that is not a JSON object is stored as one `raw` string. That covers a JSON array and a JSON body cut at the 10KB cap. Key redaction cannot look inside a string.
Evidence: the request `[{"password":"hunter2"}]` leaked. A large JSON body leaked. The response `[{"api_token":"sk_live_abc123"}]` leaked.
Fix: parse any JSON value. For a JSON content type that fails to parse or was cut, keep no raw text.

#### HTTP-2 · critical · CONFIRMED · security · `middleware/gin/gin.go:63-75`
If a later Gin middleware panics, wlog recovers it and never calls `c.Abort()`. Gin then runs the next handler. A panicking auth middleware lets the request reach the handler.
Evidence: the chain `Recovery, wlog, auth (panics), handler` returned 500 with the body `top secret`.
Fix: if the chain unwinds from a panic, call `c.Abort()` in the adapter.

#### HTTP-3 · high · CONFIRMED · G3 · `middleware/nethttp/writer.go:30-33`, `middleware/gin/gin.go:42`
Gin lets a handler change the status before the first write. `statusWriter` keeps the first status, so wlog changes the status the client gets. A 400 reached the client as 202.
Fix: forward `WriteHeader` to Gin, and read the final status from `c.Writer.Status()`.

#### HTTP-4 · high · CONFIRMED · `middleware/gin/gin.go:63-75`
Gin 404 and 405 responses are logged as status 200 at level info. A `KeepStatus(400)` sampler then drops them.
Fix: read the status from Gin after `c.Next()`.

#### HTTP-5 · high · CONFIRMED · G3 · `middleware/nethttp/writer.go:17`, `middleware/echo5/echo.go:50`
`statusWriter` has no `Unwrap` method.
- Echo v5 appends a second body after an error: `{"ok":true}` then `{"message":"Internal Server Error"}`.
- `http.ResponseController` loses `SetWriteDeadline`, `SetReadDeadline`, and `EnableFullDuplex` for every handler, which breaks SSE and long polls.
- The Echo v5 adapter never restores `c.Response()`.

Fix: add `Unwrap() http.ResponseWriter`, and restore the response.

#### HTTP-6 · high · CONFIRMED · `middleware/nethttp/recover.go:26-33`
`http.ErrAbortHandler` is recovered and not raised again. A proxied response that stopped mid-stream looks complete to the client, and it is logged as an error with a stack.
Fix: panic again with `http.ErrAbortHandler` after the event fields are set.

#### HTTP-7 · high · CONFIRMED · G4 · `middleware/nethttp/writer.go:97-109`
`ReadFrom` copies the whole stream into an unbounded buffer, then trims it to the cap. A 64MB text download allocated 128MB. No test covers it.
Fix: stop copying at the cap.

#### HTTP-8 · high · CONFIRMED · G3 · `middleware/nethttp/middleware.go:31-35,111-117`
`RequestStarter` and `RequestFinisher` hooks run with no recover. A panicking starter drops the event and the connection. SPEC.md says every hook is panic-isolated.
Fix: recover each hook call and report it.

#### HTTP-9 · high · CONFIRMED · `examples/mux`, `middleware/nethttp/config.go:87-97`
gorilla/mux stores the route on a copied request. A middleware wrapped around the router never sees it, so `http.route` is always the raw path. The conformance suite never asserts the route, so the mux proof passes. The `WithRouteFunc` doc teaches the broken setup.
Fix: use `router.Use(...)` in the example and the doc, and assert the route in conformance.

#### HTTP-10 · high · CONFIRMED · `middleware/nethttp/bench_test.go`
The 50µs p50 budget (SPEC.md criterion 9) fails on a realistic request with 13 headers, a cookie, a query, and 1KB of nested JSON.

| Setup | p50 |
|---|---|
| default, stdout JSON, 1KB response | 86µs |
| silent, no sink | 70µs |
| default, 15-byte response | 68µs |
| silent, all capture off | 20.5µs |

The repo benchmark reports a mean for a near-empty request. Redaction regex takes 33% of CPU. GC takes 17%, mostly the 10KB buffer each request allocates. With stdout on, the write syscall is the largest cost.
Fix: a realistic benchmark that reports p50, pooled buffers, no value patterns on known header keys, and a buffered stdout.

#### HTTP-11 · medium · CONFIRMED · `middleware/echo/echo.go:53-62`, `middleware/echo5/echo.go:51-60`
The Echo adapters call the error handler themselves and return nil, so outer middleware never sees handler errors. Every `echo.HTTPError`, even a 400 or a scanner's 404, becomes `level: error` and `code: INTERNAL`. net/http logs the same 404 as info.
Fix: return the error, and map the `HTTPError` status instead of storing INTERNAL.

#### HTTP-12 · medium · CONFIRMED · `middleware/gin/gin.go:67-73`, `middleware/echo/echo.go:61`
Gin `c.Errors` recorded before a panic are lost, and `c.Writer` is not restored. An Echo panic writes 500 past `echo.Response`, so outer middleware sees status 200.
Fix: move the error loop and the restore into a `defer`, and write through `c.Response()`.

#### HTTP-13 · medium · CONFIRMED · `middleware/nethttp/capture.go:11-17`, `middleware/nethttp/middleware.go:37-41`
`X-Forwarded-For` and `X-Request-ID` are trusted from any client, with no length or charset test. An 8018-byte request id was logged and echoed. `http.client_ip` accepted `evil-not-an-ip`, and that field is exempt from ipv4 masking.
Fix: add `WithTrustedProxies` with a default of `RemoteAddr` only. Replace a request id longer than 128 characters or with characters outside `[A-Za-z0-9._:-]`.

#### HTTP-14 · medium · CONFIRMED · G1 · `middleware/nethttp/capture.go:37-55`
By default, cookie and query values are captured in clear text. That includes names outside the denylist, such as `sid`, `PHPSESSID`, `code`, `key`, and `sig`. The raw `Cookie` header is masked, but the parsed copy is not. evlog does not capture cookies or query values by default.
Fix: capture cookie names only, and add common query secret names. Both are ask-first.

#### HTTP-15 · medium · CONFIRMED · `middleware/nethttp/config.go:80-85`
With no route pattern, `http.route` falls back to the raw path. That happens for a 404, a plain `http.Handler`, and chi without `WithRouteFunc`. It gives unbounded cardinality and copies secrets from the path. `/reset-password/tok_9f8e7d6c5b4a` became a route. Echo and Gin use `""` instead.
Fix: fall back to `""`, and keep the raw path only in `http.path`.

#### HTTP-16 · medium · CONFIRMED · `middleware/nethttp/body.go:68`, `middleware/nethttp/config.go:43`
Each request allocates the full capture cap. `MaxBodyCapture(1<<20)` costs 1MB per request, even for a 7-byte body. `MaxBodyCapture(-1)` panics on every request.
Fix: read through `io.LimitReader` or a pool, and clamp the value in the option.

#### HTTP-17 · medium · CONFIRMED · SPEC-http-std, SPEC-core, SPEC.md
These are in the spec and not built: `http.request_params`, `http.response_headers`, and per-route capture toggles. There is also no header allow-list, and `SkipPaths` matches exact paths only.
Fix: build them, or remove them from the spec.

#### HTTP-18 · medium · CONFIRMED · `log/slog/input.go`, `log/slog/output.go`
The slog input handler breaks slog rules:
- `With(...).WithGroup("db")` moves earlier attrs into the group.
- An `error` attr becomes `{}`.
- An empty-key group becomes `"": {...}` instead of being inlined.
- `Enabled` returns true for every level, so filtered debug records land in `logs[]`.
- The slog output drain ignores the handler's `Enabled`.

## PIPE: pipeline and backend drains

#### PIPE-1 · critical · CONFIRMED · G3 · `pipeline/pipeline.go:81-94,136-159`
The worker goroutine has no recover. A panicking `SendBatch` or `OnDropped` kills the whole process. A custom Sender is a documented extension point.
Fix: recover each attempt, and count a panic as a failed attempt.

#### PIPE-2 · critical · CONFIRMED · G2, G3, G4 · `pipeline/fanout.go`
`FanOut` starts `go d.Send(...)` for every event and every drain.

- There is no limit. A hung drain leaked 10,000 goroutines over 10,000 events.
- All drains share one map, which races.
- There is no `Close`, so `Logger.Close` never flushes a `pipeline.Wrap` inside `FanOut`.
- The comment says it waits for all drains. It does not wait.

#### PIPE-3 · critical · CONFIRMED · G3 · `pipeline/pipeline.go:70-76`
`OnDropped` runs while the buffer mutex is held.
- A panicking callback leaves the mutex locked. Every later emit then blocks the request goroutine forever.

- A slow callback delays every emit. `Send` took 501ms.

#### PIPE-4 · high · CONFIRMED · `pipeline/pipeline.go:89,195-203`, `examples/lambda/handler.go:59-63`

## AUD: audit

#### AUD-1 · critical · CONFIRMED · G5 · `audit/verify.go:21-78`
Deleting lines from the end of a journal passes `Verify`, even for a signed journal. An empty file passes too. The chain starts from `""` and stores no head, line count, or signed marker line. Without a key, anyone can rebuild a valid file, because `audit.Journal` itself writes a valid chain.

#### AUD-2 · critical · CONFIRMED · G5 · `audit/chain.go:35-49`, `audit/journal.go:51-62`
`Chain` gives out hashes under its own lock. `Journal` writes under a second lock, in arrival order. With concurrent events, lines land out of chain order. 100 concurrent `audit.Do` calls with `Chain` and `Journal` failed `Verify` in 5 of 20 runs. The `Sign` docs recommend this setup.

#### AUD-3 · critical · CONFIRMED · G5 · `audit/chain.go:27`

#### AUD-4 · high · CONFIRMED · G5 · `audit/canonical.go:12-28`, `audit/verify.go:32-62`

## SPEC: decisions the spec, plan, and interview never made

Each item names a question the process never answered. Most bugs above come from one of these gaps. Answer them in SPEC.md before the fixes, so the fixes agree with each other.

#### SPEC-G1 · data ownership
Who owns a map passed to `Set`? Is the event map that a drain receives read-only? When does a value freeze? No rule exists, and CORE-4, CORE-11, SMP-1, and PIPE-2 follow from that.

#### SPEC-G2 · redaction failure model
Does redaction fail open or closed? The question covers unknown types, a panicking transform, a body that fails to parse or was cut, and a value that fails to marshal. SPEC-redact and plan R7 disagree. A clear answer is "fail closed everywhere", with a test for each case.

#### SPEC-G3 · threat model
No document lists the untrusted inputs:
- header, query, cookie, and body key names, and their sizes
- `X-Forwarded-For`, `X-Request-ID`, CDN geo headers, and `traceparent`
- URL paths that hold tokens

No document names redaction cost as a denial-of-service path, or route cardinality as a cost path.

#### SPEC-G4 · audit guarantees
Gate G5 does not say what it promises about delivery, order, a cut file, a restart, a crash, several writers, retention, or key rotation. The spec does not say how several audit facts on one event behave, or how audit interacts with the level filter, disabled logging, and caps. The spec put chain state in core at emit, and the code moved it to drains without a spec change.

#### SPEC-G5 · drain delivery semantics
- Are drains sync or async by default?
- What happens to an emit after `Close`?
- How does a serverless handler flush without closing?
- How do drain errors reach `OnError`?
- Is delivery at most once or at least once? What about duplicates after a batch split or a partial write?

#### SPEC-G6 · value fidelity
Nothing defines the output for integers above 2^53, NaN and infinity, `time.Duration`, `time.Time`, `error`, `[]byte`, `json.RawMessage`, and `fmt.Stringer` values.

#### SPEC-G7 · event size budget
There is no total byte cap per event, no cap on nested values, and no truncation marker. Vendor line limits are not listed.

#### SPEC-G8 · time semantics
Is `timestamp` the start or the end of the work? What unit and precision does a duration use? Does an HTTP event carry one duration or two?

#### SPEC-G9 · level and outcome
How does status map to level in every adapter? How do framework HTTP errors map? Do 4xx responses from scanners count as warnings? Does outcome follow the level, the status, or the error?

#### SPEC-G10 · operation naming and route cardinality
What is `operation` for an HTTP request? What is the route for an unmatched request? How are secrets in URL paths removed?

#### SPEC-G11 · canonical shape and output shape
Do field presets change what drains, samplers, and the audit chain see? The spec never said, and CORE-12 follows from that.

#### SPEC-G12 · production capture defaults
The "capture everything" decision has no cost or privacy estimate. Two 10KB bodies per request at 1 million requests a day is about 20GB of ingest a day, before headers. Bodies hold free-text personal data that no key rule catches. evlog captures only method, path, and request id by default. Decide on a production-safe default or a named preset. Capture defaults are ask-first.

#### SPEC-G13 · sampling consistency
Four questions are open:

- Are a request and its Detach children kept or dropped together?
- Do services sample by trace id?
- Are fractional rates needed?
- Does a kept event record its sample rate, so counts can be scaled?

#### SPEC-G14 · default logger and orphan writes
Two questions are open. Do package functions work without a logger in the context, like `slog.Default`? If they do not, how does a user learn that a write went nowhere? A default logger conflicts with the rule against package state, which `SetEnabled` already breaks.

#### SPEC-G15 · wlog's own observability
The default `OnError` is silent. There are no counters for dropped events, retries, or queue depth, and no stats API. Nothing explains why an event is missing.

#### SPEC-G16 · module and release policy
The spec does not set the Go floor per module, the `require` versions between modules, the tag order, or the tidy rules outside the workspace. The workspace hid REL-2 and REL-3.

#### SPEC-G17 · performance method
The spec does not say how p50 is measured or what a realistic request is. It sets no allocation budget and no Linux numbers. It does not say whether stdout cost is inside the budget.

#### SPEC-G18 · schema versioning
Events carry no `schema_version`. There is no published JSON Schema for the event or for `wlog.map.json`. No rule says which change bumps a version.

#### SPEC-G19 · lifecycle
The spec does not cover a serverless freeze, SIGTERM, the close order between logger, pipeline, and journal, or emits after close.

#### SPEC-G20 · proof rule for the plan
Weak proof passed at every stage. A plan command that matched zero tests passed. A conformance suite that never asserts the route passed. Golden files that the code under test wrote passed. Add a rule: every acceptance criterion names a test that fails once the behavior is removed.

#### SPEC-G21 · framework reach
The parity page says Go frameworks are "all covered". chi route patterns, Fiber, gRPC, Connect, and queue consumers are not. Fiber runs on fasthttp, not net/http. Rank them by user demand.

- Redaction is on in every environment. evlog redacts only in production.
- A 30-key default denylist, `RemoveKeys` that fails on a typo, `Denies`, `Keys`, `Fingerprint`, and a Luhn test on card numbers.
- `operation` and `outcome` are first-class fields.
- `Detach` works on every framework. evlog's `fork` does not work on Hono or Nuxt.
- More enrichers: host, deployment, and CloudFront geo.
- `audit.Verify` names the failing line, and the journal resumes after a restart. A chain CLI is on evlog's roadmap.
- Money in whole micro-dollars, with `cost_unknown`.
- A performance budget and a stdlib-only root module.
- Deterministic map JSON and a `go vet` analyzer.

Several of these only count after the bugs above are fixed, such as AUD-1 to AUD-4 and RED-1 to RED-3.

## BET: better than evlog, for humans and agents

The list is ranked by value against effort. The "evlog" note says whether evlog already has the feature. Items that add or rename reserved keys, or change capture defaults, are ask-first.

#### BET-1 · fix the parity blockers first
Fix the capture-time leaks (HTTP-1, HTTP-14, RED-3), level from status (CORE-15), the baseline overwrite (CLI-5), `**` paths (SMP-3), and the silent drops (CORE-17, CORE-18). evlog: handles all of these.

#### BET-2 · `wlog query` and `wlog tail`
Filter NDJSON files, or a running app's memory endpoint, by level, time, status, code, request id, and any field. Return the newest N, group and count, and print JSON, pretty text, or a summary. The analyze skill then uses a shell command instead of Go functions. `file.Read`, `Tail`, and `memory.Filter` already exist. evlog: partly, as readers with no CLI.

#### BET-3 · `llms.txt` and `llms-full.txt`
Generate both with `make docs` from the markdown and `go doc -all`. evlog: yes.

#### BET-4 · stable problem codes for wlog's own failures
`OnError` receives a `*wlog.Problem{Code, Source, Why, Fix, Link}`. Codes include `WLOG_DRAIN_PANIC`, `WLOG_PIPELINE_DROPPED`, `WLOG_LATE_WRITE`, `WLOG_NO_LOGGER`, `WLOG_SILENT_NO_DRAIN`, and `WLOG_EVENT_TOO_LARGE`. List them in `docs/problems.md`, and build them on wlog's own `catalog`. The default `OnError` writes rate-limited lines to stderr. evlog: in the CLI only.

#### BET-5 · a `summary` field
Add one sentence per event, built after redaction. Example: `POST /orders/{id} -> 500 in 42ms: PAYMENT_DECLINED (fix: use another card)`. It helps people who scan logs, backend message columns, and LLM token cost. evlog: no.

#### BET-6 · an RFC 9457 problem+json writer
`wlogstd.WriteProblem(w, r, err)`, with Echo and Gin variants, writes `type`, `title`, `status`, `detail`, `code`, `fix`, `request_id`, and data. It never writes internal detail. evlog: yes, in a framework-specific shape.

#### BET-7 · published JSON Schemas
Ship `schema/event.v1.json` and `schema/map.v1.json`, print them with `wlog schema`, and test emitted events and drain goldens against them. Add `schema_version` to events. evlog: no.

#### BET-8 · `wlog explain`
`wlog explain <id>` covers rule ids, problem codes, reserved fields, and catalog codes, with `--json`. Add `wlog rules --json` and `wlog version`. evlog: no.

#### BET-9 · a map report built for CI and agents
Add an n/a status, file:line evidence per rule result, and `//wlog:ignore <rule> -- reason` with a suppressed count. Add a per-entry baseline diff, versions in the file, `--no-write`, a Go snippet per failed rule, and SARIF output for GitHub code scanning. evlog: yes, except SARIF.

#### BET-10 · "why is my event missing" mode
With `WLOG_DEBUG=1`, wlog prints the reason an event did not appear. Reasons include the sampling rule, the level, a disabled logger, no logger in the context, late-write keys, and an event over the size cap. evlog: partly.

#### BET-11 · agent skills in the standard layout
Write `.agents/skills/<name>/SKILL.md` with references, a CLAUDE.md with `@AGENTS.md`, and a `.well-known/skills/index.json`. Add a test that compiles and runs every snippet. evlog: yes, without the snippet test.

#### BET-12 · `wlog mcp`
A stdio MCP server with `events.query`, `events.by_request_id`, `map.entry`, `explain`, `redact.check` (built on `Redactor.Denies`), and `schema.event`. It can use the standard library only. evlog: a docs MCP server only.

#### BET-13 · human-first JSON
Use a fixed key order: timestamp, level, summary, operation, outcome, duration, service, trace, http, error, user keys, then wlog metadata. Turn off HTML escaping, nest wlog metadata under `wlog`, omit empty values, and lowercase header names. Stay inside the benchmark budget. evlog: insertion order only.

#### BET-14 · a real OpenTelemetry semantic-convention preset
Map `http.request.method`, `http.route`, `http.response.status_code`, `url.path`, `client.address`, `user_agent.original`, `error.type`, `deployment.environment.name`, and `gen_ai.*` for `llm`. Pin the semconv version. evlog: no.

#### BET-15 · pretty output worth reading
Render a tree with `key=value` for flat groups. Show the error first with the file:line of the `wlog.Error` call and a short stack. Write each event once. Turn it on for a TTY or a dev env. evlog: yes.

#### BET-16 · smarter zero config
Take the service name and version from `debug.ReadBuildInfo` (module path and `vcs.revision`). Read the env from common vars such as `APP_ENV`, `OTEL_SERVICE_NAME`, `OTEL_RESOURCE_ATTRIBUTES`, and Kubernetes vars. Accept evlog's env var names as aliases, so a team that moves from evlog renames no secrets. evlog: yes for env detection.

#### BET-17 · error detail for debugging
Add `error.caller` (the file:line of `wlog.Error`), `error.type`, and joined causes. Skip a second record of the same error. evlog: stack only.

#### BET-18 · sampling metadata
Record `sample_rate` on kept events so counts can be scaled. Keep a request and its Detach children together. evlog: no.

#### BET-19 · runtime stats
`Logger.Stats()` reports emitted events, drops by reason, queue depth, and retries. An optional `/debug/wlog` handler exposes them, and `wlog doctor --url` reads them. evlog: no.

#### BET-20 · a memory query endpoint and a real SSE protocol
Add an HTTP query handler for the memory drain. Give SSE a hello frame, a ping, a `since` parameter, and a token. evlog: yes.

#### BET-21 · a cost estimate
Show bytes per event and monthly ingest per drain from a traffic sample, in `wlog doctor` or on a docs page with real numbers. evlog: yes, as an MCP tool and a cost page.

#### BET-22 · a static StrictKeys rule
`wlog map` flags `Set(ctx, "orderID", ...)` next to a declared `NewKey("order_id")`. evlog: yes, through the TypeScript compiler.

#### BET-23 · a complete `llm` record
Add cache-write tokens, tokens per second, response id, error, embeddings, and steps. Keep money in integer micros. evlog: yes.

#### BET-24 · one event per CLI run
A small package for cobra and urfave/cli, used first by `cmd/wlog` itself. evlog: yes.

#### BET-25 · comparison pages
Compare wlog with slog, zap, zerolog, the OpenTelemetry logs bridge, and evlog. evlog: yes.

#### BET-26 · the next adapters Go teams need
Add an outbound `http.RoundTripper` that sends `traceparent` and records calls, gRPC interceptors, chi route patterns, and one queue consumer. These are "designed for" today. evlog: yes, for its own ecosystem.

## What the audit found working

- Core: sampler, enricher, and drain panics are isolated. Audit events skip the sampler. Drains get a context without cancellation.
- Redaction: the spec's token cases pass. Bad regexes and globs return errors. `Default`, `Disabled`, the `ReplaceFunc` panic fallback, the Luhn test, and the ipv4 exemptions work. The 64-goroutine race test is clean.
- HTTP: the handler still reads the full request body past the cap. Form, multipart, and binary bodies are not captured. The echoed request id cannot inject a header. Invalid `traceparent` values are rejected. Matched Gin and Echo routes are correct. The Echo v5 adapter builds against v5.3.1.
- Drains: response bodies are read and closed, the HTTP client has a 10s timeout, and status classes are right. The HTTP-date form of `Retry-After` parses. Datadog intake URLs are right for every site. Loki timestamps and stream grouping, OTLP integer strings and severity numbers, Axiom NDJSON, and the webhook signature format are correct. File mode is 0600. Every drain has a leak test.
- Audit: the journal alone chains correctly under concurrency and across a restart. An edited byte, a deleted first or middle line, reordered lines, and a wrong HMAC key are all caught.
- Catalog and llm: a duplicate code inside one registry panics. Money uses integer micros with half-up rounding. No field holds prompt or completion text.
- CLI: if no old map file exists, output is deterministic. The JSON has no absolute paths. A type error exits 2. Test files are excluded, Go 1.22 patterns split correctly, and `go vet -vettool` works.
- Build: `make race`, `make compat` on Go 1.23.0, local `make lint`, and `make map` all pass.

## Confidence and limits

The audit read every spec and the plan, and it reviewed every module. The top findings were run again or read again by a second reviewer. Coverage of known defect classes is about 95%. That is an estimate, not a guarantee.

The audit did not cover:
- file drain and `Tail` behavior on Windows
- real vendor endpoints, because no test made a network call
- the internals of the herr library
- long soak runs and heap profiles under production load
- benchmark numbers on Linux or x86
